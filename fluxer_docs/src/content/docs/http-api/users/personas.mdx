A persona is a name an account can post, react, type and signal as. Each persona has its own avatar, banner, colour, pronouns, bio, tags and signature emojis. A message sent as a persona carries its `persona_id` and a snapshot of the persona in `subprofile`, described by the [message persona](/http-api/messages/#message-persona-object) object.

The routes under `/users/@me/personas` act on the caller's own personas. [List user public personas](#list-user-public-personas) and [Get persona profile card by ID](#get-persona-profile-card-by-id) read another account's personas, [Look up personas by ID](#look-up-personas-by-id) reads what messages from given personas show, and [Get persona mention candidates for a channel](#get-persona-mention-candidates-for-a-channel) reads the personas of the people in a channel.

## Limits

An account holds at most 250 personas. Creating one more is refused with 400 `PERSONA_LIMIT_REACHED`, and so is a [bulk import](#bulk-import-personas) that would create one more.

A persona has at most five tags. A longer list is refused with 400 `PERSONA_TAG_LIMIT_REACHED`. A tag listed twice on one persona, or a tag another of the account's personas already uses, is refused with 400 `DUPLICATE_PERSONA_TAG`.

A persona has at most 10,000 signature emojis, and a longer list is refused with 400 `SIGNATURE_EMOJI_LIMIT_REACHED`. A custom emoji is identified by its ID and a Unicode emoji by its name. An emoji listed twice, or one another of the account's personas already lists, is refused with 400 `DUPLICATE_SIGNATURE_EMOJI`.

## Visibility

| Value | Description |
| --- | --- |
| unlisted | The default. Fetched by ID and offered as a mention candidate, but not listed on the owner's profile |
| public | Listed by [List user public personas](#list-user-public-personas) and offered as a mention candidate |
| private | Not listed. Its profile is refused to others; its messages, reactions and [lookup by ID](#look-up-personas-by-id) still show its name and avatar |

[Get persona profile card by ID](#get-persona-profile-card-by-id) refuses a `private` persona to anyone but its owner with 403 `PRIVATE_PERSONA`. A persona ID that does not belong to the account a route acts on returns 404 `UNKNOWN_PERSONA`.

## Selecting a persona

[Persona settings](#persona-settings-object) hold which persona the account is using. With an `active_persona_scope` of `global`, `active_persona_id` applies in every channel. With `channel`, each channel remembers its own [selection](#persona-channel-state-object), and a channel without one is used as the account itself.

Clients send a message as the selected persona by naming it in `persona_id`. A message wrapped in one of a persona's tags is sent as that persona instead, unless the persona has `auto_tag_disabled`. With an `active_persona_mode` of `last`, such a message also makes that persona the selected one.

Every change to a persona, to the settings or to a channel selection is sent to the owner's sessions as the matching [Gateway Dispatch](/gateway/events/#personas-and-signals). Most changes are also announced to every community the owner is in, and to everyone the owner shares a direct message with, as [Guild Personas Dirty](/gateway/events/#guild-personas-dirty), which lists the changes it covers.

## Bulk import personas

<RouteHeader method="POST" path="/v1/users/@me/personas/import" oauth2="personas.write" />

The older import, kept for apps that have not updated: Tyne's apps now [preview](#preview-a-persona-import) the file and [apply](#apply-a-reviewed-persona-import) one action per member. Creates or updates up to 250 personas in one request, for example from a PluralKit export. An item whose `external_uuid` matches an existing persona's `external_uuid` or ID updates that persona, and every other item creates one. The whole request is checked before anything is written and then written at once, so a refused or failed import changes nothing. Sends one [User Personas Update](/gateway/events/#user-personas-update) with the caller's full list, in place of an event per persona.

With `replace`, every live persona of the account is deleted in the same write, as [Delete persona](#delete-persona) deletes one, and every item creates a new persona. The tags, signature emojis and places under the limit of the deleted personas are free for the imported ones. A selection that named a deleted persona goes back to the account, with a [User Persona Settings Update](/gateway/events/#user-persona-settings-update) or a [User Persona Channel State Update](/gateway/events/#user-persona-channel-state-update). If the import is refused, the personas and selections stay as they were.

### Query parameters

| Field | Type | Description |
| --- | --- | --- |
| replace? | boolean | Whether to delete every live persona of the account and keep only the imported ones (default false) |

### JSON body

An array of up to 250 [persona import item](#persona-import-item-object) objects, or an object whose `personas` member is that array.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | array[[persona](#persona-object) object] | Every persona the import created or updated |

### Rate limit

30 requests per minute for each authenticated user, on the `user:persona:mutate` bucket.

## Preview a persona import

<RouteHeader method="POST" path="/v1/users/@me/personas/import/preview" oauth2="personas.write" />

Classifies each member of an import file against the caller's personas, deleted ones included, and changes nothing. Identity is the member's `external_uuid` (the PluralKit member ID, or a Tyne export's persona ID), never the name. The rules, each over every member still open before the next:

1. **The ID.** A live persona linked to the member is `up_to_date` when its details match and `differs` otherwise; failing that, a deleted one is `deleted` (the most used, if several are). Two live personas with the member's ID make it `cant_tell`.
2. **Name and tag, one to one.** The only live persona that no member of the file is linked to, with the same name and a shared tag, is `probably_same`, when no other member matches it that way and it is linked to no other member.
3. **Name or tag.** Such personas with the same name, or a tag in common (also one differing only in case), make the member `cant_tell`, with them as `candidates`.
4. **Tags.** A tag (or, from a Tyne export, a signature emoji) another live persona holds, or that another member still open has too, makes the member `tag_in_use`; both members sharing one are. Every other member is `new`.

Names compare after trimming and Unicode normalisation; tags compare as Tyne enforces them, trimmed and case-sensitive. Pictures are compared only where their origin is known (a link to the caller's own media, or one an earlier import recorded); otherwise the difference is `not_compared` and does not make a persona `differs`. A visibility difference is `info` only: applying never changes visibility. Links in the request are never fetched.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| source | string | `pluralkit` for a PluralKit export; `tyne` for a Tyne export, which also carries signature emojis and tag matching |
| members | array[object] | Up to 250 members in file order, each with the [create persona](#create-persona) fields `name`, `pronouns`, `color`, `bio`, `persona_tags`, `visibility`, `external_uuid`, `signature_emojis` and `auto_tag_disabled`, and `avatar` and `banner` objects with the file's `url` and a `hash` the client already knows is stored under the account |
| display_tag? | ?object | The file's system tag: `text` and `has_icon` |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | object | `entries` (one per member: `index`, `kind`, `persona_id`, `candidates`, `differences`, `clashes`, and the stored `avatar_hash` and `banner_hash` that are safe to show), `personas` (every persona the entries name, deleted ones included), `display_tag` (`decision`: `none`, `auto_apply` for an account with no personas and no display tag, or `ask`), `untouched` (live personas no member matched) and `needs_review` |

### Rate limit

100 requests per 10 seconds for each authenticated user, on the `user:persona:read` bucket.

## Apply a reviewed persona import

<RouteHeader method="POST" path="/v1/users/@me/personas/import/apply" oauth2="personas.write" />

Applies one action per member, checked against the account as it is now and written at once: if it is refused, nothing changes. Nothing is deleted.

- `add` creates a persona from `item`, leaving out `drop_tags` and `drop_signature_emojis`.
- `link` records `external_uuid` on `persona_id` and changes nothing else. It is refused with 400 `PERSONA_IMPORT_CONFLICT` when another live persona is linked to that member already.
- `restore` brings back the deleted `persona_id` as it was, the same persona, so its old messages and usage are its own again. Tags and signature emojis another persona holds by then are left off and listed in `dropped`.
- `use_file` replaces the details of `persona_id`, which must be linked to the item's member: name, pronouns, bio, colour and tags (an empty one clears Tyne's), the avatar and banner unless `keep_avatar` or `keep_banner` (sent when the file's picture is the same, or could not be stored), and from a Tyne export signature emojis and tag matching. Visibility is never changed.

A persona named by two actions is refused with 400 `PERSONA_IMPORT_CONFLICT`. If the result would put a tag or signature emoji on two personas, or go over the limit, it is refused with 400 `DUPLICATE_PERSONA_TAG`, `DUPLICATE_SIGNATURE_EMOJI` or `PERSONA_LIMIT_REACHED`, naming them in the message. Sends one [User Personas Update](/gateway/events/#user-personas-update) with the caller's full list.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| source | string | `pluralkit` or `tyne`, as for the preview |
| actions | array[object] | Up to 250 actions; skipped members are left out. Each has `action` and, by action, `persona_id`, `external_uuid`, `item` (a [persona import item](#persona-import-item-object) with its pictures stored), `drop_tags`, `drop_signature_emojis`, `keep_avatar` and `keep_banner` |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | object | `personas` (the personas written, in action order) and `dropped` (for restored personas, the tags and signature emojis left off) |

### Rate limit

30 requests per minute for each authenticated user, on the `user:persona:mutate` bucket.

## Delete several personas

<RouteHeader method="POST" path="/v1/users/@me/personas/bulk-delete" oauth2="personas.write" />

Deletes up to 250 of the caller's personas in one write, as [Delete persona](#delete-persona) deletes one: messages already sent as them keep showing them, and their tags, signature emojis and places under the limit become free. If one of them is not a live persona of the caller, the request is refused with 404 `UNKNOWN_PERSONA` and nothing is deleted. A selection that named a deleted persona goes back to the account, with a [User Persona Settings Update](/gateway/events/#user-persona-settings-update) or a [User Persona Channel State Update](/gateway/events/#user-persona-channel-state-update). Sends one [User Personas Update](/gateway/events/#user-personas-update) with the caller's full list, in place of an event per persona.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| persona_ids | array[snowflake] | The IDs of between 1 and 250 of your personas |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 204 | empty | The personas were deleted |

### Rate limit

30 requests per minute for each authenticated user, on the `user:persona:mutate` bucket.

## Import persona avatar from remote URL

Fetches an avatar from a remote URL and stores it. Each fetch draws on a quota of 2500 per 10 minutes for each account, shared with the batch and export image routes, and an exhausted quota is refused with 429. A URL that cannot be fetched returns 400 with a fixed `message` that does not say why.

### Response

| Status | Body | Condition |
| --- | --- | --- |

### Rate limit

20 requests per minute for each authenticated user, on the `user:update` bucket.

## Batch import persona avatars from remote URLs with streaming progress

<RouteHeader method="POST" path="/v1/users/@me/personas/import-batch-avatars" />

Fetches up to 500 avatars or banners from remote URLs and stores them, streaming progress as newline-delimited JSON (`application/x-ndjson`). Duplicate URLs are fetched once. Before streaming starts, the batch is refused with 429 when the [import quota](#import-persona-avatar-from-remote-url) cannot cover every URL, or when the caller already has a batch running. Closing the connection stops the batch, and only the URLs fetched so far count against the quota.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| urls | array[string] | List of remote avatar URLs to import |
| kind? | string | Whether the links are avatars or banners; avatars when absent |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | NDJSON stream | The [progress stream](#progress-stream) |

### Progress stream

Each line of the body is one JSON object. The first has `type` `start`, a `progress` line follows each URL as it finishes, and the last has `type` `complete`. URLs are fetched four at a time, so `progress` lines do not follow the order of `urls`.

| Field | Type | Description |
| --- | --- | --- |
| type | string | `start`, `progress` or `complete` |
| total | integer | The number of distinct URLs in the batch |
| completed? | integer | URLs finished so far, on `progress` |
| url? | string | The URL that finished, on `progress` |
| avatar_hash? | string | The stored avatar, on a successful `progress` for avatars |
| avatar_color? | ?integer | The avatar's dominant colour, on a successful `progress` for avatars |
| banner_hash? | string | The stored banner, on a successful `progress` for banners |
| error? | string | Why the URL was not imported, on a failed `progress` |
| results? | map[string, object] | On `complete`, the outcome for each URL, with the `progress` fields from `avatar_hash` to `error` |

### Rate limit

30 requests per 10 minutes for each authenticated user, on the `user:persona:batch_avatar_import` bucket.

## Look up personas by ID

<RouteHeader method="POST" path="/v1/personas/lookup" />

Returns what messages from the given personas show, whatever their [visibility](#visibility): the same fields as a message's [message persona](/http-api/messages/#message-persona-object) object, with the owner. Nothing of a persona's profile (bio, banner, pronouns) is returned. Knowing a persona's ID is enough, because an ID is only learned from something that already shows the persona, and [Guild Personas Dirty](/gateway/events/#guild-personas-dirty) never names a `private` persona. Deleted personas are returned as their old messages show them. Clients use it to refresh the personas of an account that changed them, and to name a persona a thread was started as.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| personas | array[object] | 1 to 100 personas, each as `user_id` (the owner's ID) and `persona_id` |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | array[[persona lookup item](#persona-lookup-item-object) object] | The personas found; a pair that names no persona of that user is left out |

### Rate limit

100 requests per 10 seconds for each authenticated user, on the `user:persona:read` bucket.
