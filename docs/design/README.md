# Design documents

Designs for fork features that are large enough to need one before they are built: what people
see, the decisions taken and why, and where the code will go. Each document names its issue on
tyne-chat/tyne and keeps a dated list of decisions.

A design is a plan, not a description of the code. Once a feature is built, what stays true moves
into the folder guides (`AGENTS.md` next to the code) and `ARCHITECTURE.md`, and the design document
is marked as built, or removed if nothing in it is still useful.
